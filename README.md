# Dr. Samavia – Clinical Psychologist (Flutter Android)
Purple/white bilingual starter Android app. Client: online PKR 2,000 or physical PKR 1,000, name and WhatsApp/mobile number, booking request, read-only payment methods and receipt via https://wa.me/923161454152. Admin: Firebase email/password login (UID allowlist), bookings/history, date/time confirm or reject, display name and password changes.

## Important before building
This is source code, **not a prebuilt APK**. Flutter is generated in GitHub Actions. Backend requires configuration and testing; no automatic WhatsApp messages or push notifications are implemented yet. The payment display includes Easypaisa 03161454152 (confirm this is the intended payment account) and Meezan Bank placeholder until official account details are supplied. Never send payment to an unverified account.

1. Create/verify Firebase Android app configuration for package `com.example.dr_samavia` (the package generated by `flutter create`). Firebase project ID should be `dr-samavia-clinic` only if that is the correct project. Firebase web App ID is **not** an Android App ID; obtain the Android `mobilesdk_app_id` from the Android app's `google-services.json` and use it as FIREBASE_APP_ID. Firebase options are supplied through dart defines; do not commit private admin passwords.
2. Firebase Authentication: enable **Anonymous** and **Email/Password**. Create admin email/password in Firebase Authentication; copy its **UID**.
3. Replace `AWO6CjcvAWQY6ck9iAEbQrV5aBJ2` in `firestore.rules` with the exact admin UID, then publish rules in Firebase Console > Firestore > Rules. Admin UID in build secret and Firestore rules must match. Review rules before production.
4. In GitHub repository Settings > Secrets and variables > Actions, create repository secrets: `FIREBASE_API_KEY`, `FIREBASE_APP_ID` (1:1017182355234:android:771b0e8c03877b77336f7b), `FIREBASE_SENDER_ID`, `FIREBASE_PROJECT_ID`, `FIREBASE_STORAGE_BUCKET` (optional), `ADMIN_UID`.
5. Upload contents of this folder to the **root** of a dedicated GitHub repository (not the ZIP itself). Go to Actions > Build Android APK > Run workflow. When complete, download artifact `dr-samavia-android-apk`, unzip and install `app-release.apk`.
6. Test on device: anonymous client request arrives in Firestore, admin login, confirm/reject appointment, profile/password change, WhatsApp link and Urdu/English. GitHub Actions default release APK uses a debug-generated signing key unless configured otherwise; for Play Store/public distribution, configure a permanent release signing key.

## Limitations
This version is an initial working source project, not pixel-identical to the illustrative mockup. Client has no login and cannot retrieve a booking later after app data reset. Confirmation is stored in Firestore for admin; client push notification and self-service booking status are not implemented. No in-app receipt upload. For stronger abuse protection add Firebase App Check and server-side rate limiting before public launch.
